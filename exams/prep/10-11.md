# CS473 – Algorithms I: Lecture 11
**Topic:** Greedy Algorithms
**Lecturers:** Cevdet Aykanat and Mustafa Ozdal (Bilkent University)

## 1. Activity Selection Problem

### Problem Definition
We are given a set of activities and one shared resource (e.g., a meeting room) that can only be used by one activity at a time.
*   **Input:** A set $S = \{a_1, a_2, \dots, a_n\}$ of $n$ activities.
    *   $s_i$: Start time of activity $a_i$.
    *   $f_i$: Finish time of activity $a_i$.
    *   Activity $i$ takes place in the interval $[s_i, f_i)$.
*   **Constraint:** Activities $i$ and $j$ are **compatible** if their intervals do not overlap (i.e., $s_i \geq f_j$ or $s_j \geq f_i$).
*   **Objective:** Find the maximum-size subset $A$ of mutually compatible activities.
    *   *Note:* The goal is to maximize the **number** of activities, not the total duration.

### Visual Example (Slide 5)
**Visual Description:** A timeline with integers 1 through 18. Six distinct activities are plotted as horizontal bars spanning their start and end times.
*   **Activity 1:** $[1, 4)$
*   **Activity 2:** $[2, 8)$ — Overlaps with 1 and 3.
*   **Activity 3:** $[5, 7)$ — Compatible with 1.
*   **Activity 4:** $[3, 11)$
*   **Activity 5:** $[8, 15)$
*   **Activity 6:** $[13, 18)$
*   **Objective:** We want to pick the maximum number of non-overlapping bars.

### Optimal Substructure Property
Consider an optimal solution $A$ for set $S$. Let $k$ be the activity in $A$ with the earliest finish time.
*   **Subproblem:** Let $S_k'$ be the set of activities that start after activity $k$ finishes: $S_k' = \{a_i \in S : s_i \geq f_k\}$.
*   **Claim:** $A - \{k\}$ is an optimal solution for the subproblem $S_k'$.
*   **Proof (by contradiction):**
    1.  Let $B'$ be an optimal solution to $S_k'$ such that $|B'| > |A - \{k\}| = |A| - 1$.
    2.  Construct $B = B' \cup \{k\}$. Since activities in $B'$ start after $k$ finishes, $B$ is compatible.
    3.  $|B| = |B'| + 1 > |A|$.
    4.  This contradicts the optimality of $A$. Therefore, the claim holds.

### Greedy Choice Property
**Intuition:** To maximize the number of activities, we should choose the activity that leaves the resource available for others as soon as possible.
*   **Strategy:** Choose the activity with the **earliest finish time**.
*   **Assumption:** Activities are sorted by finish time ($f_1 \leq f_2 \leq \dots \leq f_n$).

**Theorem:** There exists an optimal solution $A \subseteq S$ such that $a_1 \in A$ (where $a_1$ is the activity with the earliest finish time).

**Proof of Greedy Choice (Slide 13):**
**Visual Description:** Two parallel timelines representing sets of activities.
1.  **Top Timeline (Solution B):** Represents an arbitrary optimal solution $B = \{a_k, a_\ell, a_m, \dots\}$. The first activity is $a_k$.
2.  **Bottom Timeline (Solution B'):** Represents a modified solution. The first activity $a_k$ is replaced by $a_1$.
*   **Logic:**
    *   If $k=1$, the proof is done.
    *   If $k > 1$, we replace $a_k$ with $a_1$. Since $f_1 \leq f_k$, activity $a_1$ finishes earlier or at the same time as $a_k$. Therefore, $a_1$ is compatible with all subsequent activities ($a_\ell, a_m, \dots$) in $B$.
    *   The size $|B'| = |B|$, so $B'$ is also optimal.

### The Greedy Algorithm
1.  Sort activities by finish time.
2.  Select the first activity ($a_1$).
3.  Move through the sorted list, selecting the next activity only if its start time is greater than or equal to the finish time of the previously selected activity.

**Pseudocode (GAS):**
```text
GAS(s, f, n)
  A = {1}
  j = 1
  for i = 2 to n do
    if s[i] >= f[j] then
      A = A U {i}
      j = i
  return A
```
*   **Running Time:** $\Theta(n)$ if sorted. If not sorted, $\Theta(n \lg n)$ due to sorting.

## 2. Comparison: Greedy vs. Dynamic Programming (DP)

| Feature | Dynamic Programming (DP) | Greedy Algorithm |
| :--- | :--- | :--- |
| **Choice** | Makes a choice at each step, but the choice may depend on solutions to subproblems. | Makes the locally optimal choice at that moment. Choice depends on history, not future or subproblems. |
| **Approach** | Bottom-up strategy. | Top-down strategy. |
| **Solving** | Solves all subproblems and selects the best. | Iteratively reduces the problem to a single smaller subproblem. |
| **Key Ingredients** | Optimal Substructure, Overlapping Subproblems. | Optimal Substructure, Greedy Choice Property. |

### Proof of Correctness for Greedy
To prove a greedy algorithm works, you must show:
1.  **Greedy Choice Property:** A global optimal solution can be reached by making a local greedy choice.
2.  **Optimal Substructure:** An optimal solution to the problem contains optimal solutions to subproblems.

## 3. Knapsack Problems

### Visual Representation (Slide 40)
**Visual Description:**
*   A yellow knapsack with a weight capacity limit ($W$).
*   Various items scattered around, each with a price tag (value $v$) and a weight label ($w$).
    *   Green box: \$4, 12kg
    *   Blue box: \$2, 2kg
    *   Orange box: \$1, 1kg
    *   Gold box: \$10, 4kg
    *   Grey box: \$2, 1kg
*   **Goal:** Choose items to put in the bag to maximize total dollar value without exceeding weight $W$.

### Two Versions
1.  **0-1 Knapsack Problem:**
    *   Items are discrete (e.g., gold bricks, laptops).
    *   You must take the whole item or leave it ($0$ or $1$).
    *   **Solution:** Requires Dynamic Programming. Greedy does **not** work.
2.  **Fractional Knapsack Problem:**
    *   Items are divisible (e.g., gold dust, rice).
    *   You can take a fraction of an item.
    *   **Solution:** Solvable with Greedy Algorithm.

### Fractional Knapsack: Greedy Solution
*   **Strategy:** Calculate **value per unit of weight** ($v_i / w_i$) for each item.
*   **Algorithm:**
    1.  Sort items by value density ($v_i/w_i$).
    2.  Take as much as possible of the highest density item.
    3.  If the item runs out, move to the next highest density.
    4.  Stop when the knapsack is full.
*   **Time Complexity:** $O(n \lg n)$ due to sorting.

### 0-1 Knapsack: Why Greedy Fails (Example Slide 51-52)
**Scenario:** Capacity $W = 50$kg.
*   Item 1: $10$kg, \$60 ($\$6$/kg)
*   Item 2: $20$kg, \$100 ($\$5$/kg)
*   Item 3: $30$kg, \$120 ($\$4$/kg)

**Greedy Attempt:**
1.  Pick Item 1 (highest density \$6/kg). Remaining cap: 40kg. Value: \$60.
2.  Pick Item 2 (next highest \$5/kg). Remaining cap: 20kg. Value: \$60 + \$100 = \$160.
3.  Item 3 weighs 30kg (too heavy).
*   **Greedy Total:** \$160.

**Optimal Solution:**
*   Skip Item 1.
*   Pick Item 2 ($20$kg) and Item 3 ($30$kg). Total weight 50kg.
*   **Optimal Total:** \$100 + \$120 = \$220.
*   *Conclusion:* Greedy failed because choosing the "best" density early occupied space needed for a better combination later.

### 0-1 Knapsack: DP Solution
**Optimal Substructure:**
To solve for items $1 \dots i$ with capacity $w$:
*   If we **pick** item $i$: Value is $v_i +$ optimal value of items $1 \dots i-1$ with capacity $w - w_i$.
*   If we **don't pick** item $i$: Value is optimal value of items $1 \dots i-1$ with capacity $w$.

**Recurrence:**
$$c[i, w] = \begin{cases} 0 & \text{if } i=0 \text{ or } w=0 \\ c[i-1, w] & \text{if } w_i > w \\ \max(v_i + c[i-1, w-w_i], c[i-1, w]) & \text{otherwise} \end{cases}$$

**Algorithm (Bottom-up):**
*   Create a table $c[0 \dots n, 0 \dots W]$.
*   Fill row by row.
*   **Running Time:** $\Theta(nW)$ (Pseudo-polynomial).

## 4. Huffman Codes

### Goal
Construct an efficient binary representation for characters in a file to minimize file size (Data Compression).
*   **Idea:** Assign shorter binary codes to frequent characters and longer codes to infrequent ones.
*   **Prefix Codes:** No codeword is a prefix of another (ensures unambiguous decoding without separator markers).

### Binary Tree Representation (Slides 74-75)
**Visual Description:**
*   **Tree Structure:** A binary tree where leaves correspond to characters.
*   **Path:** Left child edge = `0`, Right child edge = `1`. The code for a character is the path from the root to the leaf.
*   **Fixed-length code:** A balanced tree where all leaves are at the same depth.
*   **Variable-length code:** A tree where frequent characters are near the top (short paths) and infrequent ones are deep (long paths).
*   **Frequency:** Each leaf holds the frequency of the character. Each internal node holds the sum of the frequencies of its children.

**Cost of a Tree $T$:**
$$B(T) = \sum_{c \in C} f(c) \cdot d_T(c)$$
Where $f(c)$ is frequency and $d_T(c)$ is the depth (length of codeword).
Alternatively: $B(T) = \sum_{i \in InternalNodes} w(i)$, where $w(i)$ is the sum of frequencies in the subtree.

### Huffman's Greedy Algorithm
1.  Create a leaf node for each character.
2.  Put all nodes in a priority queue sorted by frequency.
3.  **Greedy Step:** Extract the two nodes with the **lowest** frequencies ($x$ and $y$).
4.  Create a new internal node $z$ with $x$ and $y$ as children. Frequency of $z = f(x) + f(y)$.
5.  Insert $z$ back into the priority queue.
6.  Repeat until only one node remains (the root).

**Visual Example of Construction (Slides 84-89):**
*   **Start:** Leaves {f:5, e:9, c:12, b:13, d:16, a:45}.
*   **Step 1:** Merge min freq `f:5` and `e:9`. Create node `14`. Left child f, right child e.
*   **Step 2:** Remaining sorted: {c:12, b:13, `14`, d:16, a:45}. Merge `c:12` and `b:13`. Create node `25`.
*   **Step 3:** Remaining sorted: {`14`, d:16, `25`, a:45}. Merge `14` and `d:16`. Create node `30`.
*   **Step 4:** Remaining sorted: {`25`, `30`, a:45}. Merge `25` and `30`. Create node `55`.
*   **Step 5:** Remaining sorted: {a:45, `55`}. Merge `a:45` and `55`. Create root `100`.

**Time Complexity:** $O(n \lg n)$ due to heap operations.

## 1. Introduction to Dynamic Programming (DP)

### Concept
DP is an optimization technique used when a problem has:
1.  **Optimal Substructure:** Optimal solution contains optimal solutions to subproblems.
2.  **Overlapping Subproblems:** The same subproblems are solved repeatedly.

*   **Divide-and-Conquer vs. DP:**
    *   DAC works when subproblems are independent.
    *   DP works when subproblems overlap (share sub-subproblems). DP solves each subproblem once and stores the result (Memoization or Tabulation).

## 3. Matrix Chain Multiplication

### Problem Definition
*   **Input:** A chain of matrices $\langle A_1, A_2, \dots, A_n \rangle$.
*   **Constraint:** Matrix $A_i$ has dimensions $p_{i-1} \times p_i$.
*   **Goal:** Compute the product $A_1 \cdot A_2 \cdots A_n$ using the minimum number of scalar multiplications.
*   **Key:** Matrix multiplication is associative, so we can parenthesize it in different ways. $(A_1 A_2)A_3$ vs $A_1(A_2 A_3)$. Different parenthesizations have drastically different costs.

### Optimal Substructure
Let $m[i, j]$ be the minimum cost to compute the sub-chain $A_{i \dots j}$.
To compute $A_{i \dots j}$, we must split the product at some index $k$ (where $i \leq k < j$) such that we compute $(A_i \dots A_k)$ and $(A_{k+1} \dots A_j)$ and then multiply them.

**Recurrence:**
$$m[i, j] = \begin{cases} 0 & \text{if } i = j \\ \min_{i \leq k < j} \{ m[i, k] + m[k+1, j] + p_{i-1}p_k p_j \} & \text{if } i < j \end{cases}$$

### Visualizing the DP Table (Slides 31-44)
**Visual Description:**
*   A square matrix (or upper triangular half) is used to store values of $m[i, j]$.
*   **Axes:** Row index $i$ (1 to $n$), Column index $j$ (1 to $n$).
*   **Diagonal:** $m[i, i] = 0$ (Base case, chain length 1).
*   **Filling Order:**
    *   We cannot fill row-by-row because $m[i, j]$ depends on $m[k+1, j]$ (which is in a row below $i$).
    *   **Strategy:** Fill by **chain length** ($\ell$).
        *   First compute all chains of length 2 ($\ell=2$, diagonal just above main diagonal).
        *   Then length 3, and so on.
        *   The computation moves diagonally upward/rightward until reaching $m[1, n]$ (top right corner).
*   **Dependency Visual:** To compute a cell $m[i, j]$ (marked blue), the algorithm checks specific cells to its left (row $i$, columns $i$ to $j-1$) and below it (column $j$, rows $i+1$ to $j$). It combines these with the cost of the multiplication $p_{i-1}p_k p_j$.

### Complexity
*   **Time:** $O(n^3)$ (Three nested loops: length $\ell$, start index $i$, split point $k$).
*   **Space:** $\Theta(n^2)$ to store the table.

## 4. Longest Common Subsequence (LCS)

### Problem Definition
Given two sequences $X = \langle x_1, \dots, x_m \rangle$ and $Y = \langle y_1, \dots, y_n \rangle$, find a maximum-length sequence $Z$ that is a subsequence of both.

### Optimal Substructure
Let $c[i, j]$ be the length of the LCS of prefixes $X_i$ and $Y_j$.

**Recurrence:**
1.  If $x_i = y_j$: The last characters match. They must be part of the LCS.
    $$c[i, j] = c[i-1, j-1] + 1$$
2.  If $x_i \neq y_j$: The last characters don't match. The LCS comes from ignoring the last char of $X$ or the last char of $Y$.
    $$c[i, j] = \max(c[i-1, j], c[i, j-1])$$

### Visualizing Table Filling (Slides 102-115)
**Visual Description:**
*   **Grid:** A table with $X$ characters along the rows and $Y$ characters along the columns.
*   **Base Case:** Row 0 and Column 0 are filled with 0s.
*   **Example Trace ($X=ABCBDAB, Y=BDCABA$):**
    *   The algorithm iterates through the grid row by row.
    *   When characters match (e.g., $X[1]='A', Y[4]='A'$), the value is taken from the diagonal top-left neighbor + 1. An arrow $\nwarrow$ is conceptually drawn.
    *   When characters mismatch, the value is the maximum of the Top neighbor ($\uparrow$) or Left neighbor ($\leftarrow$).
    *   **Result:** The bottom-right cell contains the length of the LCS.

### Constructing the Solution (Slide 116)
To find the actual sequence (not just length):
*   Start at bottom-right corner $c[m, n]$.
*   If $x_i = y_j$, include this character and move diagonally up-left ($\nwarrow$).
*   If $x_i \neq y_j$, move in the direction of the larger neighbor ($\uparrow$ or $\leftarrow$).
*   Repeat until reaching row 0 or col 0.

### Optimization
*   **Space Optimization:** If we only need the *length*, we only need the current row and the previous row. Space reduces from $O(mn)$ to $O(\min(m, n))$. However, we cannot reconstruct the sequence this way (backtracking requires the full table).

## 5. Optimal Binary Search Tree (OBST)

### Problem Definition
Given a set of keys $K_1 < K_2 < \dots < K_n$ and probabilities $p_i$ that key $K_i$ is searched.
**Goal:** Build a BST that minimizes the expected search cost.
$$\text{Cost} = \sum (\text{depth}(node) + 1) \cdot \text{probability}(node)$$

### Example Visuals (Slides 129-131)
*   **Scenario:** Keywords with search probabilities (e.g., "do": 40%, "while": 23%).
*   **Non-Optimal Tree:** A balanced looking tree might put frequent words deep down.
    *   Example calculation: $1 \times 0.04 + 2 \times 0.40 \dots = 2.42$.
*   **Optimal Tree:** Places high-probability keys (like "do") near the root to minimize their depth.
    *   Example calculation: Root is "do". Total cost reduces to $2.18$.

### Optimal Substructure
Consider an optimal BST for keys $K_i \dots K_j$.
Suppose $K_r$ is the root ($i \leq r \leq j$).
*   Left subtree contains $K_i \dots K_{r-1}$ (must be optimal).
*   Right subtree contains $K_{r+1} \dots K_j$ (must be optimal).
*   **Cost Formula:**
    $$cost(T) = cost(T_L) + cost(T_R) + \sum_{h=i}^j p_h$$
    *(The sum term accounts for the fact that every node in the subtrees is one level deeper than it was in its own optimal sub-tree).*

### Recurrence
$$c[i, j] = \min_{i \leq r \leq j} \{ c[i, r-1] + c[r+1, j] \} + \sum_{h=i}^j p_h$$
*   This structure is mathematically identical to Matrix Chain Multiplication (sum of subproblems + cost of combining).
*   **Complexity:** $O(n^3)$ time, $O(n^2)$ space.
*   **Prefix Sum Optimization:** The sum $\sum p_h$ can be computed in $O(1)$ using a precomputed prefix sum array to avoid increasing the complexity to $O(n^4)$.
